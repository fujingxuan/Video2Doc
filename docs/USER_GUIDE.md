# Video2Doc 应用使用手册

3.4.1 起，最终导出目录同时保留同名 Markdown（`.md`）和可编辑 Word（`.docx`）。Word 使用相同最终正文并内嵌相关画面；任务详情中的“打开最终 Word”可直接打开。旧版已完成的历史成品不会自动补生成 Word。

## 1. 启动

双击 `dist\Video2Doc-Portable\Video2Doc.exe`。应用优先使用 `127.0.0.1:8765`；若默认端口被 AnkiConnect 等其他程序占用，会自动选择后续空闲端口并打开正确地址。启动后显示独立应用窗口，点击右上角 X 即可关闭窗口和该窗口启动的后端。应用自动升级自己的数据库，数据默认位于 `%LOCALAPPDATA%\Video2Doc`。

首次使用先打开“应用设置”，点击“重新检查环境”，确认 FFmpeg、ffprobe 和 yt-dlp 可用。缺少工具或 Gateway 时界面会显示原因，不会把未完成任务伪装为成功。

## 2. 配置 LLM、OCR 与 ASR

侧边栏把三类模型分开配置：

1. “LLM”内置本地 OneAPI、OpenAI、DeepSeek、Qwen、智谱、Kimi、SiliconFlow、OpenRouter、Gemini、火山方舟和自定义 OpenAI 兼容入口；选择平台后仍可修改 Base URL 与模型 ID。
2. “OCR”和“ASR”分别管理自己的 Gateway、协议、Base URL、超时、重试与模型。
3. 密钥可引用环境变量，也可直接填写。直接填写时仅保存 Windows 当前用户 DPAPI 密文，接口和任务快照不会回显密钥。
4. Gateway 的“连接测试”只验证服务入口；模型卡片的“测试连通性”验证具体模型。LLM 会发送一次只要求回复 `OK` 的最小 Chat Completions 实调用；ASR/OCR 会依次验证 Gateway、认证和模型目录，不上传用户媒体。
5. 每个模型可单独测试，也可点击“逐个测试全部模型”。批量测试按顺序执行，避免同时加载多个本地模型或触发云端限流；一个模型失败不会阻止其余模型继续检查。
6. 支持发现的 ASR/OCR 服务可点击“模型发现”，否则手工添加模型。Gateway 在线不再自动代表旗下每个模型均可用。
7. 内置本地 ASR/OCR 在任务需要且端口未监听时自动启动；外部 Docker 或自定义 Gateway 不由应用启动或停止。

本地 OCR 默认地址是 `http://127.0.0.1:8201`，协议是 `video2doc-ocr-http-v1`，模型是 `PP-OCRv5_server`。旧 PaddleOCR-VL 服务可使用 `paddlex-layout-parsing-v1` 适配协议。

## 3. 设置 Obsidian 与文本整理

在“应用设置”配置：

- 已存在的 Obsidian Vault 绝对路径；
- Vault 内的 Inbox 相对路径；
- 文件名、附件目录和追溯目录模板；
- 同名时自动改名、停止或带回滚覆盖；
- 是否保存 JSON sidecar、转写和字幕；
- 可选 LLM 文本模型和忠实性阈值；平台、Base URL 与密钥在“LLM”页管理。

不启用文本模型也能完成全部流程。启用后，完整正文以流式 Chat Completions 请求执行轻度整理，长输出只要持续返回数据就不会被误判为整段读超时；非流式 JSON 响应仍兼容。响应异常缩短或损坏数字、代码、公式时自动拒绝并回退原文，任务阶段会显示超时、认证、限流或忠实性校验等具体回退原因。

## 4. 新建任务

进入“新建任务”：

新建页会自动恢复上一个任务的处理方案、ASR/OCR/LLM 模型、抽帧与融合参数、字幕回退和导出目录，但不会复制上一个任务的媒体 URL 或本地文件路径。首次使用时才采用应用默认设置。

1. 选择“视频网页 URL”或“本地视频 / 音频”。
2. 本地输入可点击“选择本地媒体文件”，也可粘贴绝对路径；URL 和路径均可每行一个。
3. 选择文本来源：ASR，或“从链接抓取字幕（跳过 ASR）”。
4. 字幕模式仅接受视频网页 URL。应用先用 yt-dlp 抓取字幕轨，再尝试 B 站播放器字幕接口；字幕写入任务工作区，不要求本地字幕文件。
5. 对只有画面烧录字幕的视频，可启用“视频下方嵌入字幕 OCR 回退”并选择 OCR 模型。应用按固定间隔裁剪画面下部、过滤界面噪声并生成带时间码 SRT；所有帧、裁剪和 OCR 响应都保留在任务工作区。
6. 选择处理方案，或覆盖 ASR/OCR Gateway 与模型。字幕模式不会调用方案中的 ASR 模型。
7. 视频任务可启用完整画面 OCR，并设置抽帧策略、间隔、场景阈值、候选数和融合窗口。
8. 选择是否启用 LLM 忠实轻度整理。
9. 选择本次任务的成品导出目录；留空时使用应用设置。
10. 点击“加入处理队列”。

应用按创建顺序处理，真实 ASR 任务转写时可提前准备下一任务的音频，同时最多一个转写任务。所有耗时步骤在 Worker 中执行，关闭或刷新浏览器不会把 API 请求变成长任务。

## 5. 查看和控制任务

“任务详情”显示输入、不可变快照、attempt、错误、各阶段、媒体、ASR/链接字幕、帧/OCR、融合、Document、Markdown、产物和导出位置。每个阶段同时显示实际选用的 Gateway/模型；未调用模型的本地阶段会明确标注。Markdown 预览会按 GFM 安全渲染标题、列表、表格、代码、链接、折叠区和任务工作区内的相对图片，而不是显示 Markdown 源码。

可用操作：

- 尚未开始的等待任务：进入“编辑”，修改输入、标题和完整任务设置；保存后更新其不可变快照，开始处理后不再允许修改；
- 等待或运行任务：取消；
- 失败或中断任务：重试并复用指纹一致的有效产物；
- 等待或已结束任务：移入回收站，保留对应工作区、Markdown、附件和追溯 sidecar，可当次撤销或稍后恢复；
- 已结束任务：只清除可再生成缓存，保留任务记录和最终成品；
- 任意已有工作区任务：打开任务工作区；
- 已导出任务：打开导出目录或最终 Markdown；
- 失败任务：复制错误信息。

取消会停止后续阶段并终止由 Video2Doc 启动的外部进程树。退出 Windows 应用时，运行任务保存为可恢复状态；独立 Docker OCR 不会被停止。

运行中的任务需先取消并等待状态进入 `CANCELLED`，再移入回收站。恢复等待任务后会继续排队。回收站任务不会被后台领取，也不参与总览计数或缓存清理。

任务队列与回收站都支持标题/来源搜索、状态筛选以及每页 25/50/100/200 条记录。列表滚动时按需渲染；“选择本页”仅针对当前页，切换页面或筛选会清空选择。连接异常时自动回退到定期刷新，恢复连接后重新同步当前页。

回收站默认记录 30 天保留期，过期后不会自动删除文件。“清理过期项”在确认后每次最多永久清理 100 个过期任务，范围不受当前筛选限制。也可对所选任务执行永久删除。确认框会明确说明删除记录、工作区、Markdown、附件及追溯文件，原始媒体保留；永久删除不可撤销。目录链接、越界路径或跨任务文件引用会阻止删除。若删除中断，页面会提示文件可能不完整，可检查后重试永久删除，或恢复为失败任务后重新处理。

## 6. 结果检查

任务详情的“审阅整理差异”可按需打开原始正文与实际采用正文的并排对照，并切换逐行差异或下载完整 `.diff`。原文与成品均完整显示；来源数量、规则接受/回退状态和模型信息取自已保存产物。审阅不会重新调用模型、修改正文或阻止导出。规则校验不能替代语义判断；若模型输出被拒绝，右侧展示实际采用的回退正文。尚未生成当前 attempt 的有效 Document 时，页面会提示无法读取。

最终 Markdown 应有 YAML frontmatter、媒体来源、时长、模型/配置、一篇连续完整正文、相对图片和追溯信息。启用文本整理时，完整正文一次性提交给模型，不会按 ASR segment 分批生成；成品正文不应重复出现“讲者内容”标签或逐段来源注释。成品默认不显示媒体时间戳，也不写入生成时间字段；原始 JSON/SRT、Document 原始块和 source_id 仍保留时间与来源信息。附件和 `.data` sidecar 应与 Markdown 同名成组存在。

文本整理是忠实格式转换，不需要长链推理。对默认强制 Thinking 的 GLM 4.5 及以上模型，应用会关闭 Thinking，并以流式方式接收正文；默认总请求上限为 600 秒。网关若返回 JSON 围栏或直接返回 Markdown，应用会提取候选文章后继续执行同一套长度、数字、专名、代码和公式门禁，未通过时仍回退到完整连续原文。

如结果不符合预期，优先在任务详情检查：

- attempt 和失败阶段；
- ASR/OCR 原始响应与 normalized 产物；
- 融合时间线和 Document source_id；
- `text_edit.json` 是否使用回退；
- `export.json` 的最终路径和冲突处理结果。

Video2Doc 不生成摘要、核心观点、复习提纲、自动问答、RAG、向量索引或知识库回答。


## 3.1.0：上传音频与网页大模型校对

- 在“新建任务”选择“上传本地音频”，选择一个或多个音频文件，配置 ASR 模型并加入队列。也可继续使用本地文件路径方式。应用会保存上传副本，缓存清理不会删除该副本。
- 未勾选文本模型校对的新任务，转写后显示“待人工校对”。在队列或任务详情点击“校对 / 完成”，下载或复制初稿，自行打开常用网页大模型，上传初稿并发送页面提供的提示词。
- 将网页模型返回的完整正文粘贴到右侧，或导入 UTF-8 `.md`/`.txt` 文件。点击“保存修改稿”后可以关闭页面，应用重启后仍可继续。
- 点击“采用修改稿并完成”导出；数字缺失或大幅删减时会先显示确认提示。若不需要校对，点击“使用初稿完成”即可。两种操作均不会重新转写。
- 确认后的导出失败可在任务详情重试，已确认的稿件会继续使用。初稿和人工决定保存在工作区 `05_output/manual_review`。
- 优先字幕模式现在会在下载完整视频之前尝试字幕，逐个尝试可用人工/自动字幕与 B 站备用接口；找不到可用字幕时继续按任务设置识别。需要登录或平台限制的字幕仍可能不可用。


## 3.2 音频预取与详情内校对

- 在任务详情看到 AUDIO_VALIDATE 完成后，可点击“复制音频文件”，然后在文件夹中粘贴；也可直接下载标准化 WAV。缓存已清理的音频不可再复制。
- 下一任务准备好音频后显示 AUDIO_READY，等待前一个任务释放识别资源；取消等待中的任务不会影响正在转写的任务。
- 待人工校对时，详情内直接展示初稿和编辑区。“将初稿填入编辑区”用于手动修改，也可导入完整修改稿。保存后可稍后继续。
- “复制内容”默认合并复制校对文本和提示词，也可只选其中一项。
- 发现疑似 ASR 循环重复时，程序尝试短音频重新识别；仍有异常时保留原稿并显示音频时间范围。原始响应及质量记录保存在工作区。
- FireRedASR2-AED 单独识别模块不补标点；可在人工校对时补充。已有标点会被保留。
